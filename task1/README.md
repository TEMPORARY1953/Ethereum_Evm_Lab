# Task 1 — среднее на EVM opcodes, Cancun

Окончательная программа — [program.evm](program.evm): 139 байт, только реальные mnemonic
opcodes и числовые аргументы PUSH. Solidity, Yul, меток и макросов в ней нет.
`build_program.mjs` — вспомогательный локальный ассемблер, а не исполняемая часть решения.

## Формат calldata

```text
[N: 32 bytes][x0: 32 bytes] ... [x(N-1): 32 bytes]
```

Каждое слово — big-endian. `N` интерпретируется как знаковое int256 и должно быть > 0.
Элементы — int256 в дополнительном коде: `-1` = 32 байта `ff`.
Требуется ровно `32 * (N + 1)` байт. Selector функции, длина динамического ABI-массива
и смещение массива отсутствуют. Нули элементов допустимы.

Результат — одно 32-байтовое слово int256. `SDIV` округляет к нулю:
`(1 + 2) / 2 = 1`, `(-1 - 2) / 2 = -1`, `(-1 + 0) / 2 = 0`.

## Алгоритм и ограничения

1. Загрузить N и проверить знаковое `N > 0`.
2. Проверить размер calldata >= 64 и кратность 32.
3. Проверить `CALLDATASIZE / 32 - 1 == N`. Умножение на N не используется,
   поэтому большое N не может обойти проверку через переполнение длины.
4. Начать с суммы 0 и смещения 32. Читать слова до конца calldata.
5. При каждом сложении проверить знаковое переполнение int256.
6. Разделить сумму на положительное N посредством SDIV, записать результат и RETURN.
   Любой некорректный ввод или переполнение вызывает `REVERT(0, 0)`.

Память:

| Смещение | Значение |
| --- | --- |
| 0x00 | N, затем возвращаемый результат |
| 0x20 | накопленная сумма s |
| 0x40 | смещение следующего слова calldata |
| 0x60 | очередное значение x |
| 0x80 | результат сложения t по модулю 2^256 |

Знаковое переполнение определяется старшим битом `(s XOR t) AND (x XOR t)`:
оба слагаемых имеют знак, отличный от результата. При установленном бите — REVERT.
Все **промежуточные** суммы должны помещаться в [-2^255, 2^255 - 1].
Например `[MAX_INT256, 1, -1]` отвергается, хотя итоговая математическая сумма помещается.
Для поддержки таких последовательностей понадобился бы более широкий аккумулятор.

Время и газ линейны по N; реальный запуск дополнительно ограничен доступным gas.
Ограниченный локальный интерпретатор газ не моделирует.

## Порядок операндов, переходы и стек

Вершина стека снимается первой: SUB вычисляет `top - next`, DIV и SDIV — `top / next`.
Перед SDIV загружается сначала N, затем сумма. Перед MSTORE наверху смещение,
под ним значение; перед RETURN и REVERT наверху смещение, под ним размер.
SHR получает сверху число бит 255, под ним проверяемое слово.
Порядок сверен с [официальной Cancun execution specification](https://github.com/ethereum/execution-specs/tree/master/src/ethereum/forks/cancun/vm/instructions).

| Адрес | Назначение |
| --- | --- |
| 0x0036 | JUMPDEST: начало цикла |
| 0x007a | JUMPDEST: расчёт среднего |
| 0x0087 | JUMPDEST: REVERT |

На всех границах блоков стек пуст. Временные значения потребляются арифметическими
операциями, MSTORE, JUMP/JUMPI. Перед RETURN в стеке только `[32, 0]` (снизу вверх);
RETURN снимает оба значения. Перед REVERT — `[0, 0]`, после него также пусто.
Максимальная наблюдавшаяся глубина стека — 3.

## EVM Codes Playground

1. Открыть [официальный Playground](https://www.evm.codes/playground).
2. Выбрать hardfork **Cancun** и режим **Mnemonic**.
3. Вставить `program.evm` целиком. Не вставлять вспомогательный JS или Python.
4. В поле calldata вставить полный hex из [test_cases.md](test_cases.md).
   Если поле само добавляет `0x`, убрать один повторяющийся префикс.
5. Value = 0, gas достаточно для выбранного N; нажать Run.
6. Сравнить Return value с ожидаемыми 32 байтами либо проверить REVERT.
   Проследить стек в конце исполнения: он пуст.
7. Повторить отрицательные и некорректные случаи из таблиц.

## Локальная проверка

Из корня проекта (`python` можно заменить абсолютным путём к интерпретатору):

```powershell
node task1/build_program.mjs --check
python -B -m unittest discover -s task1 -v
```

`local_evm.py` собирает реальные байты и исполняет используемый поднабор инструкций.
Выполнены 29 фиксированных случаев и 1000 случайных последовательностей с независимым
математическим эталоном. Проверяются пустой стек, глубина и допустимые JUMPDEST.
Это не полная EVM: нет gas, world state и проверки в сторонней реализации.

Для проверки в полноценной Cancun EVM подготовлены `task4/test/AverageProgram.t.sol`:

```powershell
Push-Location task4
& ../.tools/bin/forge.exe test --match-contract AverageProgramTest -vv
Pop-Location
```

Foundry и Playground в текущей среде **не запускались**. `program.hex`, JSON-векторы
и Markdown-векторы воспроизводятся командой `python -B task1/test_program.py --write-cases`.
`program.bin` содержит те же 139 байт для `vm.readFileBinary` в Foundry: это исключает
зависимость загрузки fixture от завершающего перевода строки в текстовом hex-файле.
