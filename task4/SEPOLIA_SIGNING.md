## Действия пользователя

1. План запуска уже подтверждён пользователем; повторное подтверждение в чате не требуется.
2. Открыть страницу подписи: **http://127.0.0.1:8765/**.
3. Открыть адрес в том профиле Chrome/Edge/Firefox, где установлен существующий MetaMask.
4. Разблокировать MetaMask локально, выбрать указанный аккаунт и сеть **Sepolia**.
5. На странице нажать **«Подключить MetaMask»**, разрешить подключение только нужного аккаунта.
   Это ещё не отправляет транзакцию.
6. Нажать **«Проверить параметры deployment»**. На странице появятся сеть, chain ID,
   From, ETH Value=0, имя/символ, calldata, estimated gas fee и предельная комиссия.
   Затем нажать **«Параметры проверены — открыть MetaMask для deployment»** и отдельно
   подтвердить транзакцию в MetaMask. Без этой второй кнопки запрос подписи не создаётся.
7. Дождаться успешного receipt и двух подтверждений. Проверка RPC выполняется автоматически
   каждые 12 секунд после отправки; её также можно запустить вручную. Повторно deployment не отправлять.
8. После разблокировки mint нажать **«Проверить параметры mint»**, проверить выпуск **1 VMKRULIT**
   на ваш аккаунт, затем **«Параметры проверены — открыть MetaMask для mint»** и подтвердить
   в кошельке. Следующий этап откроется после проверки receipt, supply и вашего баланса.
9. Для transfer так же сначала проверить параметры, затем открыть MetaMask отдельной кнопкой.
   Внешний `To` — адрес токена; внутри calldata — `transfer` получателю
   `0x4a097d48ef380b479773eb609511a49cf17020f4`, количество **10^18**. ETH Value=0.
10. При сообщении об успешной RPC-проверке `FINAL_REPORT.md` уже обновлён настоящими
    deployment/mint/transfer hashes, адресом контракта, блоками и балансом получателя.

Если вкладка была закрыта во время подписи, сначала проверить историю MetaMask.
При уже отправленной транзакции не нажимать отправку повторно: использовать раздел
**«Восстановить уже отправленную транзакцию по публичному hash»** либо сообщить агенту публичный hash.
Восстановление не подписывает и не отправляет ничего. При ошибке комиссии не повышаются автоматически.

## Как устроена подпись

Foundry собирает контракт, кодирует calldata и симулирует deploy. Локальная страница
передаёт три точные транзакции **непосредственно провайдеру существующего расширения MetaMask**
через [`eth_sendTransaction`](https://docs.metamask.io/metamask-connect/evm/reference/json-rpc-api/eth_sendTransaction/).
MetaMask показывает подтверждение, подписывает и отправляет транзакцию.
Python/Foundry не получают seed, private key, пароль или подпись для произвольных данных.
Экспорт/импорт ключа и создание нового кошелька не требуются.

Страница не использует внешние JS-библиотеки/CDN. Сервер слушает только `127.0.0.1`,
проверяет Host/Origin и не имеет метода RPC для отправки транзакций.
Публичный RPC используется только для чтения. До подтверждения запускается без `--approved`.
Перед обращением к кошельку сервер сохраняет резервирование операции в `sepolia_result.json`:
оно блокирует повторы в другой вкладке и после перезапуска сервера. При неизвестном исходе
запроса блокировка сохраняется; снимается только после явного отказа MetaMask (4001),
когда точно известно, что подпись не состоялась. Hash сохраняется в браузере и проекте.
Страница допускает ровно один разрешённый аккаунт, повторно проверяет его и сеть перед подписью.
Ни approve, ни unlimited approval, ни сообщения для подписи не запрашиваются.

После подписи проверяются receipts, canonical block hash, минимум 2 подтверждения,
sender/chain/ETH value/calldata, runtime bytecode с immutable owner, name/symbol/decimals,
события mint/transfer, totalSupply и balanceOf на одном блоке.
Отчёт обновляется только после успешной проверки всех трёх транзакций.

## Команды агента

Python 3.12+ и уже установленные `.tools/bin/{forge,cast,anvil,solc}.exe`.

```powershell
# Только подготовка: тесты, read-only RPC, симуляция; без отправки.
python -B task4/scripts/sepolia_metamask.py --prepare
# Заблокированная страница для предварительного просмотра.
python -B task4/scripts/sepolia_metamask.py --serve
# Только ПОСЛЕ явного подтверждения плана: подписи всё равно подтверждаются вручную в MetaMask.
python -B task4/scripts/sepolia_metamask.py --serve --approved
# Повторная независимая проверка и обновление отчёта после отправки.
python -B task4/scripts/sepolia_metamask.py --verify
```

Не запускать параллельно `forge create --broadcast` или старые инструкции keystore:
это привело бы к отдельному deployment. `sepolia_plan.json` содержит только публичные данные.
Изменение исходников/Foundry config после подготовки блокирует использование плана.
